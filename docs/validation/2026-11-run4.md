# Validation run 4: held-out set 2, Sprint 6.8 guard (2026-11-18)

Fourth run, and the first real measurement of Sprint 6.8 (general runnability). It runs three sets together, as one
run in both fix-test modes:

- the 9 **tuning** bugs from runs 1 to 3;
- the 10 bugs of **held-out set 1** (`holdout-set.md`), plus the PySnooper-3 control;
- the 9 bugs of **held-out set 2** (`holdout-set-2.md`: ansible, fastapi, scrapy). Set 2 was chosen and reviewer-checked
  before any LegacyGuard run on it, and it has never been tuned on.

Harness: `tools/validate.py tools/validation/manifest.yaml tools/validation/holdout.yaml tools/validation/holdout2.yaml
--fix-tests both`, on main at 6336c6f plus the harness change that adds the `holdout2` set. No guard code changed for
this run. Raw output is in `2026-11-run4-raw.md` and `2026-11-run4-results.json`. Interpreter: Python 3.10.22 for
every case (macOS arm64). Wall time for the whole run (28 counted cases plus the control, each in both modes):
**203 s**.

The harness change that prints one top summary line per held-out set was made after this run. `run4.log` shows the
old one-line summary, which names only held-out set 1. The saved `2026-11-run4-raw.md` and `-results.json` already
report both held-out sets separately; they come from the same run and were not regenerated.

7 of 9 with them. It found 1 of 9 without the fix's tests and 2 of 9 with them.** One of the two found with the fix's

### Which number is evidence

- **Held-out set 2 is the clean number.** It was chosen before this run, and nothing in the guard was built while
  looking at it.
- **Held-out set 1 has influenced Sprint 6.8 indirectly.** No set-1 bug was tuned on directly. But the five general
  failure classes read from run 3's set-1 results are what Sprint 6.8 was planned around: writes during import, `self`
  not buildable, non-deterministic old code, inputs not reaching the edit, and no `bytes` inputs. Its improvement (8 to
  7 unchecked, 1 to 2 found) is therefore weaker evidence than set 2.
- **The tuning set reflects tuning**, as before.

## Setup changes before the run

These are recorded in `holdout-set-2.md`, "Setup changes before the run", and in the header of `holdout2.yaml`.

- **ansible 4 replaced by ansible 5**, by the replacement rule fixed before the run. `--check-setup` could not import
  `ansible.playbook.collectionsearch` on either tree. Its import chain loads `ansible.constants`, which creates
  `~/.ansible/tmp` at import time, and the sandbox refuses that write. No pin changes this.
- **Pin `lxml` 4.6.4 → 5.1.0 and `zope.interface` 5.5.0 → 5.5.2** (scrapy rows). The listed versions have no
  macOS arm64 cp310 wheel; each replacement is the lowest version that installs without compiling.
- fastapi 4 has its own venv with starlette 0.12.9 (a pure-Python sdist, accepted by the user's C2 decision);
  fastapi 2 and 3 use starlette 0.13.2. Transitive dependencies are pinned to the versions resolved on 2026-11-18.
- After these changes, all 28 counted cases plus the control passed `--check-setup`.

## What Sprint 6.8 moved, and what it did not

Moved:
- black-17 went from unchecked to detected. Its two run-3 causes, a cache write at import and no `bytes` inputs,
  are what 6.8a and 6.8b address.
- Set 1 went from 8 to 7 unchecked, and its untested share of functions from 35 of 38 to 27 of 38.
- Placeholder `self` (6.8c) now lets methods run where nothing could be built before: httpie-3, luigi-22, luigi-20,
  ansible-3 and scrapy-3. But a placeholder result never counts, so no case changed status through it alone.

Did not move:
- **On fresh code the unchecked share is still about 8 of 9.**
- The two largest groups on set 2 are:
  - **conditions that depend on `self` or attributes of objects**, which the 6.8e second pass cannot aim at;
  - **signatures nothing could be built for** (framework objects).
- tornado-14's blocked write is not cache-like, so 6.8a does not redirect it. The same applies to ansible's
  `~/.ansible/tmp`, which caused the setup swap.
- 6.8d did not classify the "unclassified values" noise in tornado-5 and luigi-20. It also caused a regression
  (thefuck-1).

These reason groups are the input to Sprint 7 planning. This write-up does not decide the order.

## Findings for future tasks (reported, not fixed)

1. **Regression: frozen pid breaks `psutil.Process(os.getpid())`.** `lg_worker.py` sets `FAKE_PID, FAKE_PPID = 4242,
   4241` (6.8d). thefuck calls `psutil.Process(os.getpid())` while its inputs are set up, which now raises
   NoSuchProcess. thefuck-1 went from quiet/detected to unchecked in both modes. This cause is read from the reason
   text and the code; it was not re-run by hand. Fix this first.
2. **Home-directory writes at import that are not cache-like are still refused.** ansible's `~/.ansible/tmp` is one
   (it caused the setup swap), and tornado-14's write while building `IOLoop` is another. 6.8a redirects only cache-like
   paths.
3. **ansible-3 was "verified" on a placeholder `self`.** Every changed statement was reached and no difference was
   found on 54 inputs. Yet the bug (Kali data read from `/etc/os-release`) does change the result. The line gate may
   have been met without the input that shows the bug. It is not credited either way, because placeholder results
   never count. This is worth a look, and it was not checked by hand.

## Caveats

- These are tiny samples: 9, 10 and 9 bugs. One detection more or less moves any rate a lot, so read the counts,
  not the percentages.
- ansible-5 was found with fix tests only through the fix's own test literals, which a developer would not have
  before the bug was found.
- In ansible-5 without fix tests, BugsInPy's patch did not reverse-apply. The patch also changes a test file that is
  already in its buggy form in the synthetic base. The harness put the whole buggy source file in place instead. The
  file differs by one line between the buggy and fixed commits, so the result is the same.
- False alarms were not measured: this run had no change cases.
- The group counts were read from the raw reason texts and not re-run by hand.
