runs 1 and 2, plus one control (PySnooper-3, expected unchecked). Harness: `tools/validate.py

**The number to publish is the held-out one, and it is small: 1 of 2 checked bugs detected without the fix's
tests, with 8 of 10 left unchecked.** The pooled 81.8% mixes in the tuning set the guard was built on; do not quote it.

"Unchecked" means nothing was actually compared, so the case is left out of the rate. Counting all ten held-out
bugs, the guard found **1 of 10** without the fix tests and 1 of 10 with them. That is the honest coverage figure;
the 50% above applies only to the 2 bugs where the guard managed to run the code at all.

Other numbers (without / with fix tests): untested share of functions 80.0% / 78.9%; median time per case 2.1 s /
1.9 s, p95 10.5 s / 18.8 s. The planted-bug score (4 of 8 without) comes from a single case (thefuck-1) and is not a
general score. One slowdown was flagged on youtube-dl-10 (with fix tests, also the p95 case); that case is
detected on its own real difference in `js_to_json`, and the slowdown by itself is never counted as a detection.

## What this shows

1. **The guard does not generalize yet, and the reason is not the comparison.** In 8 of 10 held-out bugs the guard
   could not run the changed code, or could not reach the changed lines. When it did run it credited one difference
   (httpie-5); a second (luigi-22, with fix tests) was seen but deliberately not credited. False alarms were not
   measured: this run had no change cases.
2. **Five general failure classes** account for the unchecked cases (read from the raw "untested" reasons;
   a case can fall in more than one):
   1. *Import or construction hit a blocked file write*: black-17 (and `format_str` in black-17/19), tornado-14.
   2. *`self` cannot be built* (required constructor arguments, no hints, no literal calls to copy): httpie-3,
      luigi-20 (`TaskProcess`), luigi-22 without fix tests (`Worker`).
   3. *Old code disagrees with itself*: tornado-5 `start`, luigi-20 `Worker.run` and `_handle_next_task`. The cause
      (object ids, threads, unfrozen time) is a hypothesis; the raw data only says the two old runs differed.
   4. *Inputs never reach the edit*: tornado-5 (callers reached 0 of 1), luigi-20 `to_str_params` (0 of 2),
      cookiecutter-2 (partial).
   5. *No inputs for the signature*: black-17 `decode_bytes(bytes)`, black-19 `_maybe_empty_lines`.
3. These are fixed generally (not per bug). Because the held-out set has now been looked at, re-measure on a
   **second, fresh held-out set**.

## Caveats

- Ten held-out bugs is a small sample; one detection out of ten has a wide interval. Treat it as a direction.
- luigi-22 is scored on outcome type only (the fixed default `time.time()` is evaluated at import), which is
  stricter than the other cases.
- The failure classes were read from the raw "untested" reasons; they were not each re-run by hand, and the cause
  given for class 3 is a hypothesis. Several cases
  also depend on pins (setuptools<82, MarkupSafe==2.0.1) noted in the manifest.
- The control behaved as expected: unchecked, because its bug shows only through a file write, which the guard
  blocks by design.
