LegacyGuard: how the guard works

What happens inside a Claude Code session while the developer and Claude change code: which code runs (the old copy, the new copy, or both), when it runs, and who is told what.

1. The one idea

The guard keeps two copies of the project and runs the changed functions in both on the same inputs.

OLD copy
The project as it was when the session started
A git worktree at HEAD, plus any uncommitted files, in .legacyguard/baseline/. It does not change during the session.
→
Same inputs, both copies
Run the changed function in OLD and NEW
Inputs: arguments seen in your tests, values written in the repo, edge values, generated values. OLD runs twice to filter out randomness.
←
NEW copy
Your working tree, with Claude's edits
The real project folder. Every Edit or Write from Claude lands here.

Before an edit · PreToolUse

no code runs

Static checks on the would-be file: frozen files, API, DB and event contracts, tests deleted or weakened. Can ask or deny. Under 1 s.

After an edit · PostToolUse, background

OLD + NEW run

The behavioral diff. Claude keeps working. If results differ, Claude is woken with the exact input and both results.

When Claude stops · Stop

OLD + NEW run

Whole-session audit, which also catches edits made with shell commands. Writes the report and the map.

4. Where it lives, and which settings control it

On the machine (installed once)

~/.claude/plugins/…/legacyguard/
  hooks/hooks.json   # events → scripts
  .mcp.json          # MCP server for Claude
  skills/            # /legacyguard:* commands
  guardlib/ runner/ indexer/ daemon/
~/.legacyguard/venv/ # the guard's OWN Python

The guard's own logic runs in its own Python. It never installs anything into your project.

In each project

your-project/
  .venv/             # YOUR Python: code under test runs here
  .legacyguard/      # git-ignored
    config.yaml      # settings (commit with git add -f)
    waivers.json     # accepted changes + reasons
    baseline/        # the OLD copy (git worktree)
    index.db         # functions, calls, routes, tests
    session.json     # findings LG-1, LG-2 …
    cassettes/       # recorded DB/HTTP replies (v1)
    guard.sock       # daemon socket (v1)
    reports/         # <session>.md and .html
  src/ …             # the NEW copy = your working tree

How it interacts with Claude Code settings

Plugin installedHooks run in every session automatically. No permission entries needed.
enabled: false in config.yamlThe guard is off for that project only.
Permission mode (default, acceptEdits, auto)Doesn't change what the guard checks. Its "ask" shows up as a normal permission prompt.
Plan modeNo edits happen, so nothing runs.
bypassPermissions"Ask" becomes allow. v1 treats such a session as advisory and says so.Today the prompt is silently skipped.
Project .claude/settings.jsonCan switch the plugin off for a repo (enabledPlugins).
ANTHROPIC_API_KEY setThe guard warns that Claude Code bills the key instead of the plan. The guard itself never calls a model.
